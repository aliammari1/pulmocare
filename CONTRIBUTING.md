# Contributing to PulmoCare

Thanks for your interest. First, the two rules that override everything else:

> [!CAUTION]
> 1. **RESEARCH ONLY — NOT FOR CLINICAL USE.** Never add a feature, claim, or
>    default that implies clinical/diagnostic use, and never remove the
>    RESEARCH-ONLY banner from AI output. PulmoCare is **not a medical device**.
> 2. **Never commit real patient data (PHI)** — no real images, identifiers, or
>    records, even in tests or fixtures. Use synthetic data only.

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Repository layout

This is a polyglot monorepo:

- `apps/api/services/<svc>/app` — independent **`uv`** Python services (auth,
  patients, appointments, medecins, medfiles, ordonnances, radiologues, reports).
- `apps/api/services/medagent` — **vendored MedRAX** (Apache-2.0). See below.
- `apps/mobile` — the **Flutter** client.
- `apps/api/docker-compose.yml` — the real orchestration (Keycloak, Vault,
  Consul, APISIX, RabbitMQ, OTel, …). The `k8s/` and `ansible/` dirs are
  aspirational.
- `docs/` — mkdocs-material source; `deploy/` — HF Space + host plans.

## The MedRAX boundary (important)

`apps/api/services/medagent` is a **vendored copy of upstream MedRAX**
([bowang-lab/MedRAX](https://github.com/bowang-lab/MedRAX), Apache-2.0).

- Treat it as a vendored dependency: **avoid editing it**. Upstream-able fixes
  belong in a PR to MedRAX; if a local patch is unavoidable, keep it minimal and
  call it out in the PR description.
- Do **not** relicense it or strip `apps/api/services/medagent/LICENSE` / the
  `NOTICE` entry. First-party PulmoCare code is MIT; MedRAX stays Apache-2.0.

## Python services (uv + ruff)

The toolchain is **uv** + **ruff** (no pip/black/poetry). Per service:

```bash
cd apps/api/services/<svc>/app
uv sync --dev
uv run ruff check . && uv run ruff format --check .
uv run ty check            # type checking
uv run pytest              # tests
```

- Format/lint with **ruff** before pushing; CI runs `ruff check` + `ruff format
  --check` and fails on diff (no `|| echo` escape hatches).
- Tests use **pytest** + `pytest-asyncio` + `httpx.AsyncClient` /
  `asgi-lifespan`. Mock MedRAX tool outputs — **no GPU/model weights in CI**.

## Flutter client

```bash
cd apps/mobile
flutter pub get
flutter analyze
flutter test
```

The committed `generated_plugin_registrant.*` / `generated_plugins.cmake` files
are regenerated by Flutter tooling — avoid hand-editing or churning them in PRs.

## Workflow

1. Fork and branch from the default branch (`feat/...`, `fix/...`, `docs/...`).
2. Use **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:`, …) — PR
   titles are validated and releases are cut by release-please.
3. Run the relevant lint/type/test commands above locally.
4. Open a PR; the `claude-code-action` reviewer flags PHI handling and any AI
   output missing the research banner.
5. Keep changes scoped; don't reformat unrelated files.

## Reporting bugs / security

- Functional bugs → GitHub issues (no real PHI in reports).
- Security/PHI issues → **private** report per [`SECURITY.md`](SECURITY.md).
